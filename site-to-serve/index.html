▶ The Simple Story

My Nintendo is a Web Server?

Yes, you are reading this correctly. Every word on this page was physically retrieved from a 1985 Nintendo Entertainment System. This isn't a simulation or a clever trick—it is real retro hardware communicating with the modern internet.

How it works:

The NES was never designed to talk to the internet, so I built a "translator." When you clicked the link to this site, your request traveled through a digital tunnel to a tiny computer (an ESP32) connected directly to the Nintendo's controller port.

The ESP32 asks the NES for the data, and the Nintendo's original 1980s processor (the 6502) "shouts" the code back across a wire. The translator then turns that raw data into the website you see before you. It's like using a vintage telegraph to send a text message.

▶ Technical Deep Dive

The Infrastructure Stack

The journey of a single packet involves several layers of hardware and software translation to bridge the 40-year gap between the NES and the modern web.

1. The Request Path

The Entryway: A Cloudflare Tunnel provides a secure entry point to a local server.

The Proxy: A reverse proxy receives the HTTP request and forwards the relevant URL parameters to an ESP32-C3 SuperMini via a high-speed serial-over-USB connection.

The Mapping: The ESP32 maps the requested URL to a unique 8-bit Request ID.

2. Hardware Interfacing

Level Shifting: The NES operates on 5V logic, while the ESP32 uses 3.3V. To prevent hardware damage, a voltage divider network using 10k resistors steps down the NES signals to a safe level for the ESP32.

The Interface: The connection is made through the NES Controller Port. The ESP32 monitors the Latch (OUT0) and Clock (OUT1) lines to synchronize data transfers.

3. The 6502 Kernel & Memory Management

The Assembly Logic: The NES runs a custom assembly program written in 6502. It stays in a low-power loop until it receives a strobe signal from the ESP32. Once triggered, it reads the 8-bit Request ID bit-by-bit.

Huffman Compression: Because the NES ROM has very limited space, the website data is pre-compressed using a Huffman Encoding tool.

Data Retrieval: The NES uses a memory-mapped lookup table to find the compressed bitstream for the requested page. It then bit-bangs the length-prefixed data back to the ESP32.

Final Delivery: The ESP32 receives the compressed stream, decodes the Huffman tree, reconstructs the original HTML, and serves it back to the reverse proxy to be displayed in your browser.
